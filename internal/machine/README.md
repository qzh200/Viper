# internal/machine

硬件层的新路线：**主路是原厂服务，固件那一侧只补它不管的几项**。

```
原厂 AcerAgentService（127.0.0.1:46933，以系统的身份运行）
        │
        │  internal/agentservice  ← 协议客户端
        ▼
   internal/machine  ← 本包：把协议的形状翻译成硬件层的形状
        │
        │  internal/hardware.Firmware（一个接口）
        ▼
固件 root\wmi\AcerGamingFunction（需要管理员权限，按需打开）
```

## 为什么走这条路

原厂服务以系统的身份运行，**程序不需要管理员权限就能用它**。本机实测：当前
会话没有管理员权限，固件那一侧连实例都找不到（`no AcerGamingFunction
instance found`），而原厂服务这一侧什么都能读。

固件那一侧读不到的东西，原厂服务都读得到：

| 能力 | 固件（WMI） | 原厂服务 |
| :--- | :--- | :--- |
| 分区颜色 | ❌ 读回来永远是全零 | ✅ 四个分区的真实颜色 |
| 灯效 | ❌ 八个灯效的结果一模一样 | ✅ 效果名、速度、方向、亮度 |
| 显卡风扇组的行为 | ❌ 只报告主风扇组 | ✅ 两组都报 |
| 每核实时频率 | ❌ 性能计数器在本机初始化失败 | ✅ 32 核每一个都有 |
| 显卡使用率 | ❌ | ✅ |
| 网络上下行 | ❌ | ✅ |
| 睿频上限 | 2419（标称频率） | 5000（真实的睿频上限） |

## 协议

```
请求： "ACER" + uint32(小端) 包标识 + JSON 负载
应答： 纯 JSON 文档 {"data":…,"request":"…","result":"0"}
包标识：0 初始化 / 10 监视数据 / 20 读设置 / 30 设备 / 40 灯效能力 / 100 写设置
结果码：0 成功 / 3 服务不实现 / 4 服务没有执行
```

客户端在 `internal/agentservice`，它只管协议，不认识硬件。这一层与协议层之间
只有两个接口：`machine.Service`（对服务）与 `hardware.Firmware`（对固件），
两边都不认识对方的实现。

## 实测得到的编码

**风扇**（`FAN_CONTROL`）：顶层 `mode` 是开关，每个风扇的 `fan_custom_auto` 与
`fan_custom_speed` 是它的行为与占空比。

| 写法 | 实测 |
| :--- | :--- |
| `mode: 0` | 自动，控制器跑自己的曲线（2722 RPM） |
| `mode: 1` | 全速，**7092 RPM** |
| `mode: 2` + `fan_custom_auto: 0` + `fan_custom_speed: 50` | 固定占空比，**4400 RPM** |

Viper 写的时候照服务自己的三个模式来：两个风扇都自动写模式 0，都全速写
模式 1，其余写模式 2。写模式 2 的话，服务档案
`HKLM\SOFTWARE\OEM\AcerAgentService\FanControl\CurrentFanMode` 里记的是「自
定义」，官方应用看到的也就不是自动了。

全速的时候服务**不看**每个风扇的数据，它只记模式，所以核对时只比模式。

**性能档位**（`OPERATING_MODE`）：编号是 `0` 静音、`1` 均衡、`4` 性能、`5` 加速、
`6` 节能，与固件那一侧的编号一样。

**显卡模式**（`GPU_MODE`）：服务从零开始数，`0` 混合、`1` 仅独显、`2` 自动。

**开关类**（`WIN_KEY`、`LCD_OVERDRIVE`、`BOOT_SOUND`、`BACKLIGHT_30S`）：形状
都是 `{"status": 0 或 1}`。`WIN_KEY` 的编号 1 表示**这个键还能用**，所以锁住
的时候是 0。

**灯光**（`LIGHTING`）：四个分区各一个颜色（`#RRGGBB`），加上效果名、速度、
方向与亮度。写入时把四个分区一起写回去，免得亮度一改就把颜色清掉。

**服务不实现的几项**：`SUPPORT_OVERCLOCKING_MODE_CAPABILITY` 的结果是 3，
`STICKY_KEY` 的写入结果是 4。这两项原厂自己也不支持，粘滞键走
`SystemParametersInfo`，超频能力走固件那一侧。

## 固件那一侧补的是哪几项

| 设置 | 为什么原厂服务给不了 |
| :--- | :--- |
| `CoolBoost` / 风扇表 | 加速在动作类 `APGeAction` 上，服务不报 |
| 超频能力 | 服务自己也不实现（结果码 3） |
| 背光原始缓冲区 | 服务只报亮度，不报那个十六字节的缓冲区 |
| 复位灯效 | 复位是固件的动作 |
| 锁 Windows 键 | **实测服务收下请求却不生效**：写 0 写 1 读回来一直是一个，等了五秒也不变。锁是固件档案里的一个位，所以这一项走固件 |

这几项要管理员权限。固件的连接是**按需打开**的，所以一台没有管理员权限的
机器照样能用上原厂服务给的那几项。连接打不开时，报的是「这一项需要固件接口，
原厂服务不提供，需要管理员权限」，不会拿别的东西冒充。

## 写完要读回核对

每一项写入之后都把配置读回来核对：灯光（颜色、效果、速度、方向、亮度）、
背光（亮度与超时）、性能档位、开关类（屏幕超频、开机音效）、风扇。机器没
有接受就在错误信息里说清楚是哪一个。

核对要**轮询一小会儿**（最多三秒）：有的设置是服务交给别的服务才生效，读
回来的值会晚一点才变。读一次就下结论会把还没生效的设置报成失败。

两个例外：

* **全速**（风扇模式 1）的时候服务不看每个风扇的数据，只记模式，所以核对
  时只比模式。
* **显卡模式**不读回核对：它写进的是杂项设置表，机器要到重启才真的换过去，
  读回来的值说明不了什么，只看服务有没有收下。

## 真机验证

`cmd/agcheck verify` 逐项改一次、读回核对、还原：

```
分区颜色       写入成功，读回核对通过，已还原
全局颜色       写入成功，读回核对通过，已还原
背光亮度       写入成功，读回核对通过，已还原
背光超时       写入成功，读回核对通过，已还原
屏幕超频       写入成功，读回核对通过，已还原
开机音效       写入成功，读回核对通过，已还原
性能档位       写入成功，读回核对通过，已还原
Windows 键  需要管理员权限，跳过
风扇全速       写入成功，读回核对通过，已还原
```

写入不只落在服务自己的应答里：灯光的写入在原厂档案
`C:\ProgramData\OEM\AcerLightingService\LightingProfile\LightingProfile.ini`
上能看到，开机音效在注册表 `boot_sound_switch` 上能看到，风扇模式在
`HKLM\SOFTWARE\OEM\AcerAgentService\FanControl\CurrentFanMode` 上能看到。
那是服务自己记下的状态，不是程序自己记的。


行为。
